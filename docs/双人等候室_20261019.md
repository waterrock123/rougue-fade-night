# 双人等候室：首阶段

## 已接入流程

大厅多人入口 → 创建/加入房间 → 两人选择角色、移动、准备 → 离开房间或返回大厅。

靠近大厅现有的多人入口，使用当前交互键进入。面板打开时关闭大厅移动、入口交互、NPC气泡和镜头缩放；关闭面板后恢复。

此阶段不启动冒险，不同步大厅NPC或战斗，不创建/修改RunStats或玩家存档。双方准备完成只显示“队伍就绪”。

## 如何测试

1. 运行两个游戏窗口，各自进入大厅，再进入多人等候室。
2. 第一个窗口填写称呼、选择角色，保留端口28080，点击“创建房间”。
3. 第二个窗口填写称呼、选择角色，房主地址填写127.0.0.1，端口同为28080，点击“加入房间”。
4. 两边都应看到两名角色、相同的成员信息。分别使用现有移动按键测试移动和朝向。
5. 分别切换角色，检查两边外观是否一致；准备后角色选择锁定，取消准备后可再次更换。
6. 双方准备后应出现就绪提示。队友离开后，房主取消准备并继续等待，可再次接受加入。
7. 房主离开/关闭窗口后，客户端应提示断线并恢复建房/加入按钮。
8. 测试取消正在连接、返回大厅、重新进入，以及返回后单人出发和继续游戏是否正常。

同一局域网的两台电脑：第二台填写房主局域网IPv4地址，不是127.0.0.1。需要房主防火墙允许该程序的对应UDP端口；本实现不会自动修改防火墙。首版没有公网中继、房间码或邀请平台，不能保证隔着不同网络直接互连。

## 脚本分工

- `scripts/hub/coop_lobby_rules.gd`：协议、角色ID白名单、人数、边界、移动和同步频率。
- `scripts/hub/coop_lobby_state.gd`：纯数据名单、准备状态、输入校验及房主移动计算。
- `scripts/hub/coop_lobby_session.gd`：ENet连接、RPC、登记、超时、断线与退出清理。
- `scripts/autoload/lobby_network.gd`：稳定节点路径的全局会话；离线时不监听端口。
- `scripts/hub/coop_lobby_panel.gd`：表单、成员显示、本机输入和按钮交互。
- `scripts/hub/coop_lobby_world.gd`：独立SubViewport中的房间展示。
- `scripts/hub/coop_lobby_avatar.gd`：复用HubPlayer外观；不读取输入、不加入player组、不运行战斗。

场景是`scenes/hub/coop_lobby_panel.tscn`与`scenes/hub/coop_lobby_avatar.tscn`。入口接在MainHomeMap已有的lobby分支。

## 同步约定

房主为1号玩家，客户端请求只使用实际网络发送者身份。只允许白名单角色ID，不能让远端指定加载任意资源。对象反序列化关闭。

名单、选角、准备使用可靠通道；输入和位置使用独立的有序不可靠通道，约20次/秒。房主推进移动，客户端只发送方向；展示角色使用平滑插值。失去输入超过350毫秒自动停步，失去窗口焦点或编辑文本时发送零输入。

当前等候区域是空房间，房主使用矩形边界限制位置，未接障碍寻路或战斗物理。此逻辑不应直接代替后续战斗中的Entity移动/碰撞。

等候室地面只读取并复用大厅现有TileSet，独立创建无碰撞地面层，不修改原资源。没有新增或消耗AI素材预算。

## 校验范围

仅执行编辑器扫描，以及`res://scripts/utils/coop_lobby_editor_check.gd`中的数据、资源绑定、会话清理和底层ENet本机回环检查。没有启动完整游戏或读写玩家存档。

本轮最终检查：60项，失败0项；新增函数长度检查通过。这里的通过范围仅为上述隔离检查，不包含完整游戏双窗口验收。

编辑器辅助SceneTree与高层RPC的根节点查找存在冲突，尝试替换测试主循环还触发了引擎崩溃，已停止该类测试。底层回环通过不等同于高层RPC/完整界面验证通过：双窗口的加入、选角、准备、移动、离开/断线仍需按上述步骤手动确认。

扫描仍可能报告项目原有的consumable_stone_manifest.tscn UID回退及退出时资源清理告警，本任务不修改这些既有问题。
