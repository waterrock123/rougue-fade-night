# 百宝罐

## 生效规则

- 每件已装备百宝罐独立记录本人击破地图物件的次数；宠物、敌人击破、动物死亡和拾取物消失不计数。
- 炼金站触发伤害阈值掉落不算击破，实际死亡才算。
- 满10次清空计数，在击破位置延迟生成宝罐；普通/大奖及具体装备在生成时决定，拾取不重抽。
- 标记写入 Relic.effect_counters，与属性加成分开；跨战斗、卸装与保存读取保留。
- 合成沿用现有系统：保留被选为合成基础的那件装备的数据，不合并多件的标记。
- 普通大奖概率5%，升级态10%；两种奖励池的内部权重独立于大奖概率。
- 普通池等权重：金币+2、恢复5生命、恢复10能量、随机一件不高于商店等阶的装备。
- 大奖：金币+5与随机一件不高于商店等阶的升级态装备。
- 装备候选来自当前商人，兼容其禁售与偏好权重；商人缺失时使用全装备池。
- 随机使用战斗随机流，不影响事件/商店的 RunRng。
- 未拾取宝罐随战斗场景清理，不跨关卡保存；宝罐掉落后卸下百宝罐仍可领取。
- 装备装不下时宝罐保留，腾出空间后重试，重试不重抽也不重复发放金币；奖励池没有装备时提示并只发放仍有效的组合奖励。

## 复用与美术

- MapDestroyCountLootEffect：配置击破阈值、排除标签、概率和两个奖励池。
- MapLootReward：配置权重及金币、生命、能量、随机装备组合。
- MapLootPickup：复用浮动、吸附、出生弹跳、预抽装备和统一拾取提示。
- scenes/battlemap/map_loot_pickup.tscn 的 VisualRoot/Sprite2D 留空，请补宝罐贴图；暂时以“宝罐/大奖宝罐”文字区分，大奖文字为金色。
- 不消耗此前素材生成剩余预算，也未调用收费素材接口。

## 测试步骤

1. 调试器添加并装备百宝罐，先把 required_count 改为2快速验证，再恢复10。
2. 玩家击破两个岩石/苹果树后应只掉落一个宝罐；宠物击破、怪物死亡、动物死亡不增加计数。
3. 把概率临时改为0或1，分别验证普通四个奖励及大奖，测完恢复0.05/0.1。
4. 商店2阶时生成装备宝罐，确认装备不超过2阶；升级商店或重新触碰同一宝罐不会重新抽奖。
5. 累积部分标记，正常完成战斗，在修整期卸下再穿上并进入下场战斗，标记应保留；退出继续遵循现有检查点回退，不保存尚未完成战斗的新进度。
6. 多件百宝罐独立累计；触发装备刷新后下一次击破不应多次计数。
7. 全背包满时碰触装备宝罐，腾出空间后再试，应领取原奖励且大奖金币只发一次。
8. 战斗退出、死亡或结算淡出时，不应继续生成宝罐或残留全局信号连接。

## 校验

仅执行编辑器扫描、静态引用与格式检查，不运行游戏；需手动验证碰撞和奖励结算。
