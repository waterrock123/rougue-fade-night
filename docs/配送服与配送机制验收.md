# 配送服与配送机制

## 规则

- 每件已装备配送服每场战斗生成一份货物，只能配送一次。
- 货物和目的地从玩家可达区域随机选择，默认相隔至少120；小地图无合适位置时允许缩短距离。
- 拾取货物后才出现目的地，携带期间获得加权随机效果。
- 示例池等权重：力量+3、敏捷+3、速度+10。可在配送服效果的 cargo_options 中配置权重、名称和 RelicEffect 列表。
- 仅组合支持成对 on_activate/on_deactivate 的可撤销效果，不要在货物池中配置永久奖励或只有 on_use 的效果。
- 普通态送达获得1金币，升级态获得3金币；送达立即移除货物加成。
- 死亡、战斗结束、真正卸下配送服时取消任务，撤销加成，不奖励金币；退出不保留货物。
- 装备控制器全量刷新不会重复发货或撤销正在配送的效果。
- 战斗随机使用普通随机数，不消耗商店/事件种子流；重进战斗不保证货物位置或效果相同。

## 场景美术

- 货物：scenes/battlemap/delivery_cargo.tscn。
- 目的地：scenes/battlemap/delivery_destination.tscn（继承货物交互基础场景）。
- 已绑定 Meowa 生成的力量木箱、敏捷布袋、速度货物与金色向下箭头，可在 VisualRoot/Sprite2D 或货物池选项的 icon 中替换。
- 目的地箭头轻微上下浮动；地面圆圈保持静止，半径直接读取 CollisionShape2D 的 CircleShape2D.radius。
- 每个货物池选项的 icon 与效果一起抽取，取货前下方显示加成文字，避免仅靠颜色猜效果。
- CollisionShape2D 控制触碰范围；lifetime=0 不过期，enable_magnet=false 不自动吸附。
- 角色头顶显示取货/送达方向与距离，交互点也有文字；战斗左侧消息记录取货及完成结果。

## 手动验收

1. 用局内调试器获得并装备配送服，进入战斗，确认只有一个货物并可抵达。
2. 触碰货物，确认只有一项示例加成生效；货物消失，出现一个送达地点，提示改为送达方向。
3. 到达地点，确认普通态金币+1、升级态+3，加成和目的地消失，不再生成第二份货物。
4. 在携带期间让其他装备触发装备刷新，确认任务和加成保留，不重复增加。
5. 未送达时结束战斗、死亡或返回大厅，确认无配送金币与残留加成；进入下一场战斗重新生成。
6. 用两件配送服测试独立任务、独立效果键与奖励，不互相覆盖。
7. 小地图与复杂回环地图测试两个交互点都在可达区域内；暂停时不会完成配送或生成新任务。
