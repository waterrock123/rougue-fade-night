# 主动技能元素标签

## 三套数据独立

- `ActiveSkillData.element_tags`：技能身份，用于元素联动，不自动显示在技能UI中。
- `SkillData.tags`：原有分类，如projectile、buff、equipment_skill；保持原逻辑。
- `DamageData.damage_types`：真实伤害类型，继续决定成长、免疫与伤害数字颜色。

例如护盾术属于magic元素但不造成伤害；贵人射线普攻的技能身份仍是magic，额外激光的真实伤害可以是LIGHTNING。元素标签不会自动改变伤害或附加状态。

## 已配置

| 技能 | 元素 |
| --- | --- |
| 火球术、喷射火焰 | fire（火） |
| 闪电箭 | lightning（雷） |
| 护盾术、加速咒、贵人基础攻击 | magic（魔力） |
| 冰锥齐射 | ice（冰） |
| 眼镜蛇大炮 | poison（毒） |

其他技能默认无元素，不根据已有普通标签或伤害类型自动猜测。
一个技能可以配置多个元素，同种元素重复填写不增加计数；大小写、空白会在读取时统一。

## 检查器配置

打开主动技能资源，在“技能元素（隐藏）/Element Tags”数组添加fire、ice、lightning、magic、poison等标识。
允许直接扩展新的StringName，比如wind，不需要修改枚举或数据库；同一个元素应统一标识。
怪物或召唤物只有Ability场景、没有ActiveSkillData时，设置Ability的Fallback Element Tags。
一旦绑定ActiveSkillData，就以资源为准；资源数组为空也不会改读场景后备值。

## 查询接口

ActiveSkillData、Ability与AbilityContext都提供：

```gdscript
ability.has_element_tag(&"fire")
var wanted: Array[StringName] = [&"fire", &"lightning"]
ability.matches_element_tags(wanted)       # 任一匹配
ability.matches_element_tags(wanted, true) # 全部匹配
```

统计当前实际携带的技能，不受能量和当前冷却影响；不会把未携带的备用技能算进去：

```gdscript
var wanted: Array[StringName] = [&"fire"]
var skills: Array[Ability] = controller.get_abilities_with_elements(wanted, false, false)
var fire_skill_count: int = skills.size() # 第三个参数false排除基础攻击
```

一次伤害的来源技能元素：

```gdscript
func _on_damage_dealt(data: DamageData) -> void:
    if data.has_skill_element(&"fire"):
        pass # 在这里执行火元素技能命中的联动
```

`SkillElementFilter`是可导出到效果资源中的筛选配置，只负责匹配，不直接产生游戏效果：

```gdscript
@export var element_filter: SkillElementFilter

func _on_ability_triggered(ability: Ability, _caster: Entity) -> void:
    if element_filter != null and element_filter.matches_elements(ability.get_element_tags()):
        pass # 执行后续效果
```

筛选资源支持Required Elements、Require All、Excluded Elements。没有要求时不限制，有任意排除元素则拒绝；“排除”优先。

## 事件选择与快照

- 每次成功开始施法：继续监听AbilityController.ability_triggered。吟唱沿用原语义，在开始时触发，不代表已经吟唱完成。
- 每枚投射物真实生成：EventBus.projectile_launched提供AbilityContext，可读取context.element_tags。
- 每次有效造成伤害：Entity.damage_dealt提供DamageData，可读取skill_element_tags。

上下文创建时读取技能元素；分裂、扇形、径向、连续射击和二级地面实体继承快照。Manifest在激活时复制，命中时写进DamageData。
技能栏重建、卸下技能或修改原技能资源，不会改变已经发出的弹体的元素。
元素数组逐级复制，修改伤害事件中的数组不会反向污染原技能或其他弹体。

装备、地图和状态的独立伤害默认没有技能元素，不会仅因为属于FIRE伤害就自动算作fire技能，以免产生错误联动和递归触发。
新增自定义Manifest若覆写activate，需要调用capture_element_tags(context)；创建DamageData后，在apply_damage前调用stamp_damage_elements(data)。直接伤害组件可使用context.stamp_damage_elements(data)。

## 存档与测试

有路径的技能继续按资源恢复，旧存档无需迁移；无路径的技能备用序列化分支已加入element_tags，缺失字段视为空数组。
只进行编辑器扫描和隔离函数测试，不启动游戏、不读写玩家存档。后续具体联动技能可直接复用本框架，没有额外赠送任何战斗加成。
